## v10 → v12 디자인 판단의 변화

v10·v11은 기존 사이트의 스타일을 확장한 작업이었으며, 당시 CHR 하네스를 직접 읽고 적용한 것은 아닙니다. 승률 링·리본·지도·그래프가 추가되었지만 화면은 여전히 세로로 긴 보고서였고, 한 영역의 선택이 다른 영역으로 연결되지 않았습니다. 사용자는 이를 인터랙티브하지 않고 심심하다고 평가했습니다.

v12에서는 실제 `CHR_Web_Harness_r6`의 문서를 읽었습니다. 다만 하네스의 문서 사이트 생성기나 ISF 템플릿을 실행한 것이 아니라, 기존 앱의 개인 성적 화면에 디자인·표현·검증 원칙을 적용했습니다.

핵심 변경은 다음과 같습니다.

1. 지도·챔피언 선택을 공통 필터로 만들어 통계·그래프·경기 목록이 함께 바뀌게 했습니다.
2. 그래프 표면과 전체 타임라인에서 경기를 직접 선택하고, 조작 중 상세 수치가 갱신되게 했습니다.
3. 최다 킬·어시스트·무데스 하이라이트가 실제 해당 경기를 가리키게 했습니다.
4. 탐색/경기 목록/상세 통계를 나눠 같은 수치가 계속 반복되는 세로 길이를 줄였습니다.
5. 모바일은 큰 지도 대신 5개 라인 버튼을 사용하고, 필터 변경 후 포커스와 선택을 유지했습니다.

이 변경이 사용자의 미적 기대를 충족했다는 후속 평가는 아직 없습니다. 코드 구현·테스트 통과·게시 완료까지만 확인된 상태입니다.

## 확정되지 않은 요구를 다루는 원칙

- 대화에 등장하는 이전 기능 제안의 ‘2번 기각, 3~7번 수용’ 번호만으로 원래 제안 내용을 새로 추정하지 않습니다. 실제 구현과 명시적으로 남은 요구를 기준으로 이어갑니다.
- 자체 평점·MVP/ACE·내부 MMR의 공식은 미확정입니다. 임의 점수로 UI를 채우지 않습니다.
- 현재의 티어·선호 라인 기반 셔플은 유지합니다. 개인 성적 기반 밸런싱은 향후 별도 정책·알고리즘 작업입니다.
- 과거 모바일 접속 문제 이후 공용 서버 상태와 반응형 구현이 존재하지만, 현 패키지 시점의 실기기 동작 완료를 보증하는 자료는 없습니다.
- 캡처 이미지에서 읽을 수 없는 닉네임·시간·수치를 추정하지 않습니다. 외부 에이전트 출력에도 null과 관리자 매칭 절차를 유지합니다.
