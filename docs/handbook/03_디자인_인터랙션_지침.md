# 디자인·인터랙션 지침

기준: 2026-10-08 KST, 개인 성적 탐색 개편(v12)의 현재 소스. 이 문서는 실제 구현과 향후 유지해야 할 의도를 함께 기록한다. 화면의 재미·완성도를 사용자 검증으로 확인했다는 뜻은 아니다.

## 1. 사용자가 요구한 경험

목표는 내전 성적을 정확히 읽을 수 있으면서, 한눈에 봤을 때 “재밌다”는 느낌이 들고 직접 만져 볼 이유가 있는 개인 페이지다. 사용자는 앞선 결과에 “전혀 인터랙티브하지도 않고 심심함”이라고 지적했다. 따라서 다음 작업에서 단순히 그래프·장식·애니메이션 수를 늘리는 방식으로 만족을 가정하면 안 된다.

이번 개편의 방향은 **선을 그려 놓은 보고서에서, 라인·챔피언·경기를 직접 고르는 탐색 화면으로 바꾸는 것**이다. 모든 선택에는 통계 범위 변경, 선택 경기 변경, 근거 경기 열기처럼 구체적인 결과가 있어야 한다.

| 변경 | 의도 | 현재 구현 |
|---|---|---|
| 짧은 프로필 상단과 승패 링 | 누구의 성적인지, 전체 기록이 어떤지 먼저 인식 | 선수명·현재 닉네임·티어·주/부 포지션·승패·승률·누적 통계 |
| 연결된 탐색 영역 | 분리된 카드보다 하나의 조사 흐름 제공 | 라인·챔피언 선택을 통계·그래프·경기 목록·상세 통계에 공통 적용 |
| 3개 보기 | 긴 세로 보고서와 반복 정보 축소 | 탐색 / 경기 목록 / 상세 통계 |
| 그래프 직접 조작 | 표시된 수치와 특정 경기를 연결 | 그래프 터치·드래그, 키보드, 경기 버튼, 이전·다음 |
| 전체 경기 타임라인 | 최근 12경기 밖의 과거 기록도 탐색 | 전체 범위 슬라이더와 이동식 12경기 표시 창 |
| 근거가 있는 하이라이트 | “잘한 순간”을 직접 찾아볼 계기 제공 | 최다 킬·최다 어시스트·무데스 기록에서 해당 경기 선택 |
| 짧은 전환 | 선택 결과를 인지하기 쉽게 보조 | 초기 등장·보기 전환, 명시적 모션 끄기 및 OS 설정 대응 |

## 2. 하네스 적용 범위와 이력

- v10/v11 작업에서는 CHR Web Harness 원문을 직접 읽지 않았다. 당시의 하네스 직접 준수를 주장하지 않는다.
- v12에서는 실제 `CHR_Web_Harness_r6.zip`의 `HARNESS.md`, `docs/DESIGN.md`, `docs/DIAGRAMS.md`, `docs/INTAKE.md`, `docs/QA.md`를 참고했다. 저장소의 `docs/player-explorer-design.md`에 적용 범위와 검증 기록이 남아 있다.
- **하네스의 디자인·정보 표현·검수 원칙을 기존 앱에 적용했다. 하네스의 문서 사이트 생성기를 실행하거나, 앱 전체를 하네스 런타임으로 교체한 것은 아니다.**
- ISF 배너·안랩 명칭·예시 페이지 수·테마 전환 런타임을 이 프로젝트에 복사하지 않았다. 하네스 예시의 레이아웃 치수도 앱에 그대로 강제하지 않았다.
- 사용자가 진인프라 로고 제거를 요청했으므로 **로고를 복원하지 않는다.** 하네스에 브랜드 예시가 있어도 현 프로젝트 지시가 우선한다.

## 3. 시각 언어

| 항목 | 현재 기준 / 유지 지침 |
|---|---|
| 글꼴 | 프로젝트 내 Paperlogy를 사용한다. 실제 동봉 파일과 `@font-face`는 **400 / 700 / 800**이다. 하네스의 500/600 항목을 근거로 해당 폰트 파일도 포함됐다고 적지 않는다. 일부 CSS가 500/600을 요청해도 이는 별도 파일 존재를 뜻하지 않는다. |
| 중심 색 | 남색 `#00176A`, 파랑 `#003E9C`, 흰색. 개인 프로필 상단은 `#001B59` 계열이다. |
| 본문·면·선 | 본문 `#333333` / `#4D4D4D`, 연한 면 `#F8FAFE` / `#F0F3F9`, 얇은 경계 `#E1E6F2`. 탐색 영역은 범위가 제한된 자체 토큰을 갖는다. |
| 승패 | 승리 파랑, 패배 적갈색 계열에 WIN/LOSS 또는 승리/패배 텍스트를 함께 사용한다. 색만으로 구분하지 않는다. |
| 구성 | 남색 프로필 → 누적 핵심 지표 → 탐색 작업 영역. 작은 카드나 의미 없는 그래프를 늘려 공간을 채우지 않는다. |
| 수치 | 승률 1자리, KDA 2자리, CS/분 1자리. 정렬된 숫자·단위·표본 수를 함께 보여준다. |
| 이미지 | 임의 선수 아바타·외부 캐릭터 이미지를 만들지 않는다. 현재는 코드 기반 SVG/CSS, 텍스트 챔피언 이름으로 작동한다. 나중에 공식 아이콘을 쓰더라도 매칭 실패 시 이름으로 기능을 유지해야 한다. |

현재 탐색 페이지는 최대 폭 1440px를 사용한다. 하네스의 일반 읽기 화면 최대 폭 1600px·목차 폭 248px 등을 이 앱의 실제 구현값으로 혼동하지 않는다.

## 4. 정보 범위: 상단 누적과 선택 범위를 섞지 않는다

`경기`는 시리즈 전체가 아니라 **플레이한 1세트**다. 날짜 필터는 페이지의 원천 조회 범위를 먼저 정한다.

| 화면 부분 | 집계 범위 | 라인·챔피언 선택 영향 |
|---|---|---|
| 상단 선수 프로필·승패 링·핵심 누적 수치 | 선택 경기일 전체. ‘전체 경기일’이면 모든 경기일 | 바뀌지 않음. ‘라인·챔피언 필터 적용 전’ 명시 |
| 탐색 범위 요약 | 선택 경기일 ∩ 실제 플레이 라인 ∩ 챔피언 | 경기 수·승패·승률·KDA·CS/분 갱신 |
| 탐색 그래프·하이라이트 | 위 선택 범위 | 같은 범위로 갱신 |
| 경기 목록·최근 폼 | 위 선택 범위 | 같은 범위로 갱신 |
| 포지션·챔피언·동료 상세 | 위 선택 범위 | 같은 범위로 갱신 |
| 계산 기준의 완료 시리즈 안내 | 현재 경기일 전체 기준 | 범위 안내를 유지하며 필터 통계로 오인하지 않게 표시 |

라인 필터는 등록된 주/부 포지션이 아니라 **경기에 저장된 실제 position**을 사용한다. 선택 칩은 개별 해제할 수 있고 전체 초기화가 가능하다. 교집합 0건은 “이 조합의 경기가 없습니다”와 초기화 동작을 보여준다. 다른 선수를 선택하거나 날짜를 변경하면 탐색 상태는 초기화된다.

## 5. 그래프의 상호작용 계약

1. 지표는 KDA / CS·분 / 챔피언 피해량 중 고른다. 서로 다른 단위를 한 축에 섞지 않는다.
2. 표시 창은 최대 12경기이며 왼쪽이 오래된 경기, 오른쪽이 최신 경기다. 전체 경기 타임라인은 표시 창 밖의 기록까지 이동한다.
3. 그래프 위 native range input의 `input` 이벤트로 커서·선택 경기 수치·경기 버튼을 즉시 갱신한다. 드래그 중 해당 입력 요소를 통째로 교체하지 않는다.
4. `change` 시 선택 경기와 표시 창 시작점을 페이지 상태에 넘긴다. **창 안에서 끌 때는 창이 따라 움직이지 않는다.** 밖의 경기를 선택할 때만 창을 옮긴다.
5. 선택은 배열 인덱스만으로 보관하지 않는다. 현재 `seriesId`와 `gameId` 또는 `setNumber`로 만든 안정적인 키를 사용한다. 닉네임 변경, 신규 경기 삽입, 지표 변경 뒤에도 같은 경기를 가리킨다. 삭제된 경기는 실제 남은 경기로 다시 선택한다.
6. 키보드 방향키, Home/End 등 native slider 동작과 이전·다음 버튼을 제공한다. 경기 1건이면 불필요한 range 조작은 비활성화한다.
7. 하이라이트는 정확한 원천 경기로 이동한다. 최고 기록이 같으면 최신 경기, 무데스 기록이 여러 개면 가장 최근 무데스 경기를 선택한다.
8. 실제 경기의 상세 보기와 데모의 로컬 상세 팝업을 분리한다. 데모 경기로 존재하지 않는 운영 기록 URL을 만들지 않는다.

## 6. 데이터 시각화에서 지켜야 할 사실성

- 경기 기록이 유일한 통계 원천이다. 시각화를 위해 숫자를 DB에 별도 저장하지 않는다.
- 미수집 `null`은 `—` 또는 미수집으로 표현한다. 실제 0과 다르다. 결측 구간을 0까지 내리거나 선으로 연결하지 않는다.
- Death 합계가 0인 KDA는 Perfect다. 무한대·임의 상한값으로 그리지 않고 수치 축 밖의 별도 마커로 나타낸다. 모든 값이 Perfect/미수집이면 숫자 축을 억지로 만들지 않는다.
- CS/분은 CS와 시간이 모두 있는 경기만 사용한다. 평균 수치는 항목별 수집 경기 수를 함께 표시한다.
- 포지션 지도와 챔피언 빈도는 플레이 횟수다. 실력·티어·MMR처럼 보이게 의미를 바꾸지 않는다.
- 하이라이트는 완전한 K/D/A 수집 경기에서의 최다 킬·어시스트·무데스 사실이다. Score, MVP, ACE, MMR을 추정하는 장치가 아니다.
- 선택 범위와 전체의 승률 차이는 `%p`로 표시한다. Perfect를 일반 숫자처럼 빼서 KDA 차이를 만들지 않는다.

## 7. 모바일·접근성·모션

- 데스크톱 포지션 지도와 모바일 간결한 라인 버튼은 같은 필터를 제어한다. 모바일에서 숨겨진 지도로 포커스가 되돌아가지 않도록 현재 보이는 컨트롤을 우선한다.
- 주요 버튼·슬라이더는 44px 이상의 터치 영역을 목표로 구현했고, 모바일 라인 버튼은 52px 높이를 사용한다. 이 수치는 CSS 확인 결과이며 실제 기기 터치 검수와는 별개다.
- 작은 화면은 범위 요약을 2열로, 선택·버튼은 줄바꿈 가능한 구조로 배치한다. 검색·선택 입력은 모바일 16px를 사용한다.
- 긴 이름·챔피언명은 줄바꿈한다. 버튼의 선택 상태는 `aria-pressed`, 동적 요약은 `aria-live`, 경기 슬라이더는 `aria-valuetext`로 전달한다.
- 새로 렌더한 뒤 가능한 한 조작하던 컨트롤로 포커스를 복원한다. 더 보기 버튼이 사라지면 경기 목록 제목으로 이동한다. 데모 dialog 종료 시 이전 트리거로 복귀한다.
- 모션은 처음 들어올 때와 짧은 보기 전환의 피드백으로 사용한다. 새로고침·경기 선택마다 전체 그래프를 재생하지 않는다. 자동 재생은 없다.
- 명시적 모션 끄기와 `prefers-reduced-motion`은 등장 애니메이션, hover 이동, 부드러운 스크롤에 대응한다. 설정은 브라우저 선호이며 경기 데이터를 수정하지 않는다.

## 9. 다음 디자인 리뷰에서 물어야 할 것

“애니메이션이 있다”를 성공 조건으로 쓰지 않는다. 처음 접한 사용자가 설명 없이 라인과 챔피언을 고를 수 있는지, 그래프를 끌어 볼 생각이 드는지, 하이라이트에서 특정 경기를 다시 보고 싶은지, 내 기록을 공유하고 싶은지를 확인한다. 특히 사용자의 ‘심심하다’는 평가가 해소됐는지는 아직 재확인하지 않았다.
